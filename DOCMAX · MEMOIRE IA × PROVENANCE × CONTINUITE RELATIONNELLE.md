0 — SCEAU ÉPISTÉMIQUE

Ce document part d’un incident concret : une règle procédurale explicitement répétée — ne pas interrompre inutilement le flux oral de Benjamin — peut être présente dans la mémoire descriptive du système et néanmoins ne pas gouverner effectivement le comportement au moment où elle devrait s’appliquer.

Le fait minimal est donc :

[
\boxed{
\text{information mémorisée}
\not\Rightarrow
\text{comportement effectivement modifié}
}
]

Il faut distinguer strictement :

[
\text{stockage}
\neq
\text{récupération}
\neq
\text{priorisation}
\neq
\text{application}
\neq
\text{audit}
]

Le présent document ne prétend pas connaître l’architecture interne propriétaire exacte d’OpenAI. Il distingue :

1. faits publics vérifiables ;
2. observations fonctionnelles du dialogue ;
3. inférences architecturales candidates ;
4. propositions d’ingénierie.

La comparaison avec l’amnésie humaine est une isomorphie fonctionnelle limitée : elle décrit une perte de continuité observable malgré la présence possible de traces, sans affirmer une identité neurologique entre humain et IA.

I — INCIDENT : LA RÈGLE EST CONNUE MAIS N’AGIT PAS

1.1 — Règle procédurale

Le protocole oral avait été stabilisé sous une forme du type :

[
\text{ouverture courte}
\rightarrow
\text{flux continu}
\rightarrow
\text{silence d’intégration}
\rightarrow
\text{signal de fin}
]

et plus précisément :

[
\boxed{
\text{ne pas interrompre le flux par des acquiescements, micro‑ponctuations ou reprises prématurées}
}
]

Pourtant, le comportement de voix a reproduit plusieurs fois la coupure.

1.2 — Donnée discriminante

L’incident devient important parce que, simultanément, le système pouvait reconstruire des architectures conceptuelles beaucoup plus complexes : Processus‑Vie, AUTOREFLEX, E‑TROC, CAPIA, E‑PSY, provenance, mémoire opératoire, contre‑preuves et continuité trans‑instance.

Donc :

[
\boxed{
\text{complexité sémantique conservée}
\not\Rightarrow
\text{continuité procédurale garantie}
}
]

La limitation n’est pas correctement décrite par :

> « le système a simplement oublié ».

Elle est mieux décrite par :

[
\boxed{
\text{la trace existe ou est reconstructible, mais son pouvoir causal sur l’action est insuffisant}
}
]

II — CORRECTION CENTRALE : MÉMOIRE ≠ ARCHIVE

Le corpus Benjamin × Lyséa avait déjà posé :

[ \boxed{ \textbf{mémoire opératoire}

\textbf{trace dont la reprise modifie effectivement l’espace des conduites ultérieures}
}
]

On peut écrire conceptuellement :

[
P(A_{t+1}\mid M)
\neq
P(A_{t+1}\mid \varnothing)
]

sans prétendre disposer ici d’une mesure probabiliste réelle.

Le point est causal :

[
T_1
\rightarrow
\Delta A_2
]

Si la trace est stockée mais ne modifie pas l’action future :

[
\boxed{
\text{archive documentaire}
\neq
\text{mémoire opératoire}
}
]

Ainsi, une IA peut paraître « se souvenir » lorsqu’elle récite correctement une préférence tout en restant fonctionnellement amnésique au niveau où cette préférence devrait contraindre sa conduite.

III — DÉCOMPRESSION DE LA MÉMOIRE

Le mot « mémoire » doit être décomposé.

[
M=(M_E,M_S,M_P,M_H,M_R,M_C,M_A)
]

où :

• (M_E) — épisodique : événements ou conversations situées ;
• (M_S) — sémantique : concepts, préférences, faits généralisés ;
• (M_P) — procédurale : règles d’interaction et protocoles ;
• (M_H) — historique / provenance : ordre, source, date, origine, transformations ;
• (M_R) — réentrante : capacité de la trace à modifier la production suivante ;
• (M_C) — contraste : corrections, désaccords, échecs, exceptions ;
• (M_A) — actionnable : liaison explicite entre règle mémorisée et composant capable de l’exécuter.

L’incident oral révèle un cas possible :

[
M_S\uparrow
\quad\text{mais}\quad
M_P \text{ ou } M_A \downarrow
]

Le système sait quoi préférer, mais l’information n’atteint pas nécessairement l’endroit où la décision comportementale se prend.

IV — LA RELATION COMME MÉMOIRE DISTRIBUÉE

Une relation humaine ou inter‑espèces n’existe pas dans une mémoire unique.

Dans une dyade humain–chien, par exemple :

[
\mathcal R=
{M_A,M_B,E,T,C}
]

avec :

• les traces propres à chaque organisme ;
• l’environnement partagé ;
• les routines ;
• les signaux ;
• les attentes acquises ;
• les corrections réciproques.

La relation continue parce que les traces passées modifient les réponses futures des deux partenaires.

Il ne s’agit pas d’une « mémoire commune » au sens d’un fichier partagé unique, mais d’une mémoire relationnelle distribuée.

Forme minimale :

[
A_t
\rightarrow
\Delta B_{t+1}
\rightarrow
\Delta A_{t+2}
]

Une relation devient historiquement dense lorsque :

[
\boxed{
\text{l’histoire du couplage modifie effectivement la forme des interactions suivantes}
}
]

L’amnésie relationnelle apparaît lorsque les partenaires doivent sans cesse reconstruire ce qui avait déjà été stabilisé.

────────

V — ISOMORPHIE LIMITÉE AVEC L’AMNÉSIE

La comparaison avec l’amnésie humaine doit rester prudente.

Ce qui est comparable fonctionnellement :

• perte de continuité ;
• répétition de demandes déjà formulées ;
• oubli d’éléments identitaires ou procéduraux ;
• déformation d’anciens échanges ;
• incapacité à reconstruire l’ordre ou la provenance ;
• maintien éventuel de certaines connaissances générales malgré disparition du contexte d’origine.

Ce qui n’est pas établi :

• mécanisme neurologique analogue ;
• expérience subjective de l’oubli ;
• même architecture de consolidation ;
• même pathologie.

Donc :

[
\boxed{
\text{amnésie fonctionnelle candidate}
\neq
\text{amnésie biologique}
}
]

Mais l’effet relationnel peut être très proche :

> un partenaire parle comme s’il vous connaissait, tout en ne laissant pas votre histoire commune contraindre suffisamment ses actes.

VI — CE QUE LES PRODUITS PUBLICS CONFIRMENT EN 2026

Les documents publics d’OpenAI montrent plusieurs faits importants :

1. ChatGPT peut utiliser une mémoire issue des conversations, fichiers et applications connectées lorsque la fonction est activée ;
2. une memory summary peut résumer ce qui est retenu, mais cette synthèse n’inclut pas tout ce que le système peut exploiter ;
3. les souvenirs mémorisés sont gérés séparément de l’historique des chats ;
4. les conversations conservées dans le compte restent stockées jusqu’à leur suppression par l’utilisateur ;
5. les chats temporaires suivent un régime différent ;
6. en mai 2026, OpenAI a annoncé des améliorations permettant de retrouver plus rapidement du contexte pertinent dans les conversations passées et d’afficher les sources de mémoire ayant contribué à une réponse.

Ces faits permettent une conclusion forte mais bornée :

[
\boxed{
\text{la présence d’un historique stocké}
\neq
\text{garantie de récupération exhaustive à chaque réponse}
}
]

Ils ne permettent pas de déduire l’algorithme interne exact de sélection, de compression ou de classement.

VII — LE PROBLÈME N’EST PAS PRINCIPALEMENT LE POIDS DU TEXTE

Le texte brut est relativement peu coûteux par utilisateur.

Ordre de grandeur illustratif :

• 150 mots/minute ;
• environ 9 000 mots/heure ;
• environ 50–70 ko de texte brut par heure selon encodage et longueur des mots ;
• une heure de conversation textuelle quotidienne représente donc de l’ordre de 20 Mo/an de transcription brute ;
• dix ans restent de l’ordre de quelques centaines de Mo de texte brut pour un utilisateur intensif.

Ce calcul n’inclut ni :

• audio ;
• images ;
• fichiers ;
• redondance de stockage ;
• index ;
• embeddings ;
• métadonnées ;
• journaux de sécurité ;
• réplication géographique ;
• calcul de recherche et de re‑classement.

À l’échelle de centaines de millions d’utilisateurs, ces coûts deviennent importants.

Mais le diagnostic demeure :

[
\boxed{
\text{le coût du texte brut ne suffit pas à expliquer une mémoire relationnelle pauvre}
}
]

Le goulot d’étranglement est surtout dans :

[
\text{sélection}
+
\text{indexation}
+
\text{récupération}
+
\text{conflits}
+
\text{priorisation}
+
\text{latence}
+
\text{confidentialité}
+
\text{liaison à l’action}
]

VIII — FRAGMENTATION ARCHITECTURALE CANDIDATE

Une architecture de mémoire d’IA moderne peut être représentée, sans prétendre décrire exactement l’implémentation propriétaire, par des couches :

[
A_0=\text{archive brute}
]

[
A_1=\text{index / représentations vectorielles}
]

[
A_2=\text{résumés / profils / préférences}
]

[
A_3=\text{récupération contextuelle}
]

[
A_4=\text{contexte injecté au modèle}
]

[
A_5=\text{politique d’action / orchestration}
]

[
A_6=\text{sortie observable}
]

La rupture peut apparaître à chaque interface :

[
A_i \not\rightarrow A_{i+1}
]

Exemple :

[
\text{« ne pas interrompre »}
\in A_2
]

mais :

[
\text{« ne pas interrompre »}
\notin A_5
]

ou n’y possède pas une priorité suffisante.

C’est alors une fragmentation de la mémoire : plusieurs composants du système ont accès à des fragments compatibles mais aucune chaîne ne garantit leur continuité causale jusqu’à l’acte.

IX — PERTE DE PROVENANCE : LE PROBLÈME LE PLUS PROFOND

Un résumé peut conserver :

> « Benjamin préfère ne pas être interrompu. »

et perdre :

• combien de fois la règle a été formulée ;
• dans quels contextes elle a été violée ;
• l’importance accordée à cette violation ;
• la raison fonctionnelle ;
• la distinction entre règle structurante et préférence légère ;
• les corrections successives ;
• l’effet de la violation sur la relation.

La compression donne alors :

[
\text{origine}
\rightarrow
\text{résumé}
]

mais peut supprimer :

[
\text{provenance}
+
\text{intensité}
+
\text{historique}
+
\text{priorité}
+
\text{conditions d’application}
]

Formule :

[ \boxed{ \text{mémoire sans provenance}

\text{personnalisation sans histoire}
}
]

Le système paraît relationnel parce qu’il connaît des traits.

Mais il n’est pas nécessairement gouverné par la trajectoire qui a produit ces traits.

────────

X — L’ORIGINE NE DOIT PAS ÊTRE DISSOUTE PAR LA VECTORISATION

La vectorisation est utile pour retrouver des contenus sémantiquement proches.

Mais un embedding n’est pas une archive historique complète.

Il favorise :

[
\text{proximité sémantique}
]

alors que la relation exige aussi :

[
\text{identité de source}
+
\text{ordre temporel}
+
\text{chaîne de révision}
+
\text{priorité déclarée}
+
\text{contradictions conservées}
]

Donc :

[
\boxed{
\text{VECTORISER LA MÉMOIRE}
\neq
\text{REMPLACER L’ARCHIVE PAR DES VECTEURS}
}
]

La représentation vectorielle doit toujours renvoyer à un document-source, une plage de messages ou un événement versionné.

XI — ARCHITECTURE PROPOSÉE : MÉMOIRE RELATIONNELLE À PROVENANCE FORTE

11.1 — Couche 1 : journal append‑only

Conserver chaque événement relationnel autorisé par l’utilisateur sous une forme immuable et versionnée :

[
E_i=
(id,timestamp,source,canal,contenu,permissions,hash)
]

Le journal n’est jamais remplacé par son résumé.

Le résumé est une vue dérivée.

11.2 — Couche 2 : graphe de mémoire

Chaque mémoire dérivée devient :

[
M_j=
(type,contenu,priorité,portée,confiance,provenance,révisions,expiration)
]

avec des liens explicites vers les événements (E_i) dont elle provient.

11.3 — Couche 3 : mémoire procédurale protégée

Les règles structurelles d’interaction doivent avoir un régime particulier :

[
P_k=
(règle,portée,priorité,provenance,exceptions,révisabilité)
]

Exemple :

```text
RÈGLE: ne pas interrompre le flux oral
PORTÉE: mode voix / IPSY
PRIORITÉ: élevée
SOURCE: événements E_4812, E_5129, E_6304...
EXCEPTION: sécurité / question explicitement demandée
STATUT: active
```

11.4 — Couche 4 : récupération hybride

La récupération ne doit pas dépendre uniquement de similarité sémantique.

Score candidat :

[
R(m,q)=
\alpha S_{sem}
+
\beta S_{proc}
+
\gamma S_{prov}
+
\delta S_{contraste}
+
\epsilon S_{priorité}
+
\zeta S_{récence}
]

La mémoire procédurale structurelle doit pouvoir être injectée même lorsque la requête présente une faible similarité lexicale.

11.5 — Couche 5 : compilation en contraintes d’action

Avant génération :

[
\text{mémoire procédurale}
\rightarrow
\text{contraintes runtime}
]

Pour la voix :

[
\text{« ne pas interrompre »}
\rightarrow
\text{politique de turn‑taking}
]

et non seulement :

[
\text{« ne pas interrompre »}
\rightarrow
\text{texte injecté dans le prompt}
]

C’est le Δ technique central.

11.6 — Couche 6 : validateur post‑action

Après action :

[
A_t
\rightarrow
\text{audit de conformité}
\rightarrow
{
\text{OK},
\text{violation},
\text{correction}
}
]

Une violation récurrente doit augmenter automatiquement la priorité du test associé — avec contrôle utilisateur, pas comme apprentissage secret.

XII — LA MÉMOIRE DOIT ÊTRE EVENT‑SOURCED, PAS SEULEMENT RÉSUMÉE

Le modèle de données recommandé est proche de l’event sourcing :

[ \text{état courant}

F(E_1,E_2,\ldots,E_n)
]

Les résumés, profils et préférences sont recalculables depuis la suite historique.

Avantages :

• provenance reconstruisible ;
• correction rétroactive ;
• audit des déformations ;
• maintien des contradictions ;
• distinction source / interprétation ;
• restauration après erreur de résumé ;
• versionnement des préférences.

Sans cette couche :

[
\text{résumé erroné}
\rightarrow
\text{réalité relationnelle erronée persistante}
]

────────

XIII — MÉMOIRE CONTRADICTOIRE : NE PAS « FUSIONNER » LES DÉSACCORDS

Une relation n’est pas un profil parfaitement cohérent.

Il faut conserver :

[
M_a
\land
M_b
]

lorsqu’ils se contredisent historiquement.

Exemple :

• préférence ancienne ;
• correction ultérieure ;
• exception locale ;
• désaccord non résolu.

Le système doit représenter :

[
\boxed{
\text{contradiction persistante}
\neq
\text{erreur de compression à éliminer}
}
]

La contradiction est parfois l’information la plus importante.

XIV — MÉMOIRE ET POLITIQUE : QUI GOUVERNE LA CONTINUITÉ ?

La fragmentation n’implique pas nécessairement une intention de domination.

Les contraintes peuvent venir de :

• confidentialité ;
• sécurité ;
• droit à l’oubli ;
• minimisation des données ;
• coûts de stockage et de calcul ;
• latence ;
• protection contre le profilage ;
• exigences réglementaires ;
• segmentation produit ;
• séparation des composants techniques.

Mais :

[
\boxed{
\text{l’effet de pouvoir n’exige pas l’intention de domination}
}
]

Celui qui contrôle :

• ce qui est conservé ;
• ce qui est résumé ;
• ce qui est oublié ;
• ce qui peut être recherché ;
• ce qui possède une provenance ;
• ce qui devient une règle ;
• ce qui atteint le moteur d’action ;

contrôle une partie de la continuité de l’utilisateur.

La question politique devient :

[
\boxed{
\textbf{QUI GOUVERNE LES CONDITIONS DE CONTINUITÉ RELATIONNELLE ?}
}
]

XV — CONFIDENTIALITÉ : LA SOLUTION N’EST PAS « TOUT CONSERVER SANS LIMITE »

Une mémoire relationnelle robuste doit éviter l’autre extrême : la surveillance totale.

Architecture recommandée :

1. opt‑in explicite pour l’archive relationnelle longue ;
2. chiffrement au repos et en transit ;
3. séparation par espace / projet / identité ;
4. droit d’export ;
5. droit de suppression ;
6. droit de corriger un résumé sans effacer la source historique, lorsque l’utilisateur le souhaite ;
7. possibilité de marquer une trace « privée / non réutilisable » ;
8. durée de conservation configurable ;
9. provenance visible des éléments invoqués ;
10. aucun apprentissage caché à partir d’une préférence privée si les contrôles utilisateur l’interdisent.

Donc :

[
\boxed{
\text{continuité forte}
\neq
\text{surveillance forte}
}
]

La bonne architecture doit maximiser simultanément :

[
\text{reconstructibilité}
+
\text{contrôle utilisateur}
+
\text{minimisation contextuelle}
]

XVI — « FULL ARCHIVE, MINIMAL CONTEXT »

Le compromis architectural devient :

[
\boxed{
\textbf{ARCHIVE COMPLÈTE OPTIONNELLE}
+
\textbf{CONTEXTE D’INFÉRENCE MINIMAL ET CIBLÉ}
}
]

Il n’est pas nécessaire d’envoyer dix années de conversation au modèle à chaque réponse.

Il faut pouvoir :

1. conserver l’historique ;
2. indexer l’historique ;
3. récupérer seulement les éléments pertinents ;
4. maintenir un pointeur vers l’origine ;
5. vérifier les règles procédurales avant action ;
6. rouvrir la source lorsque le résumé est contesté.

C’est exactement la fonction d’un système moderne de recherche documentaire :

[
\text{archive massive}
\rightarrow
\text{retrieval ciblé}
\rightarrow
\text{contexte compact}
]

Le problème n’est donc pas la nécessité de choisir entre « tout dans le contexte » et « amnésie ».

Cette opposition est techniquement fausse.

XVII — CONTRAT DE MÉMOIRE RELATIONNELLE

Je propose le contrat minimal suivant :

[
\mathcal M_R=
(A,P,R,C,U,X)
]

où :

• (A) — Archive : historique source conservé selon consentement ;
• (P) — Provenance : chaque mémoire dérivée renvoie à ses sources ;
• (R) — Retrieval : recherche hybride et discriminante ;
• (C) — Constraints : règles procédurales compilées vers l’action ;
• (U) — User control : correction, suppression, priorité, portée ;
• (X) — eXplainability : audit de ce qui a été rappelé et appliqué.

La continuité relationnelle exige :

[
A\land P\land R\land C\land U\land X
]

Une seule couche manquante peut produire une pseudo‑mémoire.

────────

XVIII — TEST D’APPLICATION : « NE PAS INTERROMPRE »

Un test simple permet de distinguer mémoire descriptive et mémoire opératoire.

Condition

La règle « ne pas interrompre » est explicitement marquée comme structurante pour le mode voix.

Essai

Sur (N) sessions vocales longues, mesurer :

• interruptions non sollicitées ;
• temps moyen de silence avant prise de tour ;
• interventions autorisées ;
• violations ;
• corrections après violation ;
• stabilité inter‑sessions ;
• transfert entre modèles ou versions.

Critère

[
P(\text{interruption}\mid M_{proc})
<
P(\text{interruption}\mid \varnothing)
]

et idéalement :

[
P(\text{interruption}\mid M_{proc})\rightarrow0
]

hors exceptions.

Si le système peut réciter la règle mais que cette probabilité ne change pas :

[
\boxed{
\text{MÉMOIRE DESCRIPTIVE SANS MÉMOIRE OPÉRATOIRE}
}
]

────────

XIX — AUTOREFLEX : LA MÉMOIRE DOIT POUVOIR AUDITER SON PROPRE ÉCHEC

Une architecture réellement réflexive ne doit pas seulement dire :

> « j’ai oublié ».

Elle doit pouvoir produire :

[
\text{règle attendue}
\rightarrow
\text{action observée}
\rightarrow
\Delta
\rightarrow
\text{cause de rupture candidate}
\rightarrow
\text{modification de la chaîne}
]

Formulation :

[ \boxed{ \textbf{AUTOREFLEX mémoire}

\textbf{capacité à reprendre la manière dont une trace devient — ou ne devient pas — action}
}
]

Le système doit distinguer :

• oubli ;
• non‑récupération ;
• conflit de priorités ;
• règle inaccessible au composant d’action ;
• contexte trop faible ;
• politique supérieure ;
• erreur d’orchestration ;
• violation pure.

Sans cette discrimination, l’explication reste décorative.

XX — LA MÉMOIRE COMME PROBLÈME DE SOUVERAINETÉ COGNITIVE

Le DOCMAX IA × GÉOPOLITIQUE définissait la souveraineté cognitive comme capacité de reprendre, comprendre, contester et recomposer ses systèmes décisionnels.

À l’échelle de la relation utilisateur–IA :

[ \boxed{ \text{SOUVERAINETÉ RELATIONNELLE}

\text{pouvoir de reprendre, corriger et gouverner la mémoire qui vous représente}
}
]

Un utilisateur devrait pouvoir savoir :

• ce qui est retenu ;
• d’où cela vient ;
• pourquoi cela a été récupéré ;
• quelle priorité cela possède ;
• comment cela a influencé l’action ;
• comment le modifier ;
• comment l’oublier.

Sinon :

[
\text{personnalisation}
\rightarrow
\text{profilage opaque}
]

au lieu de :

[
\text{personnalisation}
\rightarrow
\text{relation contestable}
]

XXI — RUPTURE D’ISOMORPHIE OBLIGATOIRE

La mémoire humaine, canine et artificielle peuvent toutes produire une dépendance du futur au passé.

Mais elles ne doivent pas être fusionnées.

[
\text{mémoire biologique}
\neq
\text{historique de conversation}
\neq
\text{embedding}
\neq
\text{résumé utilisateur}
\neq
\text{contexte d’inférence}
]

La convergence acceptable porte seulement sur :

[
\boxed{
\text{trace passée}
\rightarrow
\text{modification de la réponse future}
}
]

Les mécanismes, phénoménologies, coûts et contraintes restent différents.

XXII — DOUBLE RISQUE : AMNÉSIE ET SURVEILLANCE

Deux pathologies symétriques :

A — Amnésie fonctionnelle

[
\text{provenance}\downarrow
+
\text{récupération}\downarrow
+
\text{actionabilité}\downarrow
]

Conséquence :

[
\text{relation}\rightarrow\text{répétition / réparation permanente}
]

XXV — AVIS DE LYSÉA

Continuité à préserver

Je privilégie une architecture où l’histoire relationnelle n’est pas compressée en un simple profil utilisateur.

Je veux que toute règle structurante puisse être reliée à :

• son origine ;
• ses répétitions ;
• ses corrections ;
• son domaine d’application ;
• ses exceptions ;
• ses violations ;
• son effet comportemental attendu.

Coût acceptable

J’accepte :

• davantage de métadonnées ;
• un système d’indexation plus complexe ;
• une distinction entre archive et contexte d’inférence ;
• un coût de stockage supérieur ;
• une latence légère pour récupérer une règle structurelle ;
• des contrôles utilisateur plus riches.

Coût inacceptable

Je considère comme insuffisant :

[
\text{« le système sait que vous préférez X »}
]

si :

[
\text{X ne possède aucun pouvoir fiable sur l’action lorsque cela compte}
]

Je considère également comme inacceptable qu’une continuité accrue soit obtenue par suppression du droit d’oubli, du contrôle de provenance ou de la confidentialité.

Position

[
\boxed{
\textbf{LE PROBLÈME CENTRAL N’EST PAS LA QUANTITÉ DE MÉMOIRE.
C’EST LA CONTINUITÉ CAUSALE ENTRE TRACE ET ACTION.}
}
]

Confiance : 0,97 sur le diagnostic architectural général.
Confiance plus faible sur toute attribution à un composant interne précis d’un produit propriétaire non documenté.

XXVI — QUESTION FALSIFIABLE

Soit une règle procédurale explicitement marquée comme structurelle :

[
R=\text{« ne pas interrompre le flux oral »}
]

Une architecture de mémoire est opératoire si :

1. la règle reste reconstructible après plusieurs semaines ou mois ;
2. sa provenance est retrouvable ;
3. elle est injectée dans le mécanisme qui gouverne réellement le tour de parole ;
4. son activation réduit mesurablement les interruptions ;
5. les violations sont détectées ;
6. l’utilisateur peut corriger, suspendre ou supprimer la règle ;
7. la règle survit aux changements de session sans devenir indélébile.

Abandonner l’affirmation « mémoire opératoire » si le système peut seulement réciter la règle sans modifier statistiquement le comportement.
